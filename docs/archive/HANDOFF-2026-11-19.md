# Handoff: PC Engine CD-ROM emulator on the expansion port (Tang Nano 20K)

Context from a chat with Claude (2026-11-19). Goal: a CD-ROM² / Super CD-ROM² emulator that plugs
into the PC Engine / TurboGrafx-16 rear expansion port, derived from a stripped-down PCEHeroTN
(https://github.com/terracide303/PCEHeroTN-Beta, a PC Engine core for the Tang Nano 20K).

## Platform decision
- Tang Nano 20K (GW2AR-18): FPGA = deterministic bus timing. Chosen over RP2350B (risky ~140 ns
  read latency at 7.16 MHz) and Raspberry Pi/Linux (cannot answer bus cycles at all).
- Tang Nano 9K would fit a CD-only build, but has no companion MCU, no DAC, ~58 KB BSRAM
  (the 64 KB CD RAM must go in PSRAM), and some 1.8 V I/O banks.
- Full PCEHeroTN core is already full on the 20K, so the expansion version must be stripped down.

## What the expansion device must provide
- CD controller registers in the $1800 I/O page
- 64 KB CD work RAM at banks $80–$87
- ADPCM (MSM5205-style) + 64 KB ADPCM RAM
- CD-DA audio, mixed back into the expansion port's audio lines (analog)
- 192 KB Super System Card RAM (when emulating the Super System Card)
- Sector/CD-DA streaming from CUE/BIN images on microSD via the companion MCU (Pico/BL616)
- A System Card in the HuCard slot is still needed (unless its BIOS is emulated too)
- Reference HDL for the CD logic: the MiSTer TurboGrafx-16 core (GPL)

## Strip / keep / add (from PCEHeroTN)
- Strip: HuC6280 CPU (+MMU/timer/IRQ), HuCard/mapper/ROM loading, gamepad/USB/DB9/turbo, most of the menu
- Keep (HDMI phase): VDC, VCE, PSG as *shadow* chips, HDMI encoder, SDRAM controller
- Add: bus interface (decode, level-shifter control, snoop), CD controller, ADPCM, CD-DA mixer, RAM in SDRAM
- Check the Gowin per-module hierarchy report before cutting

## Hardware notes
- Pin budget: A0–A20 (21) + D0–D7 (8) + /RD, /WR, clock, reset, IRQ2 (~5) + buffer dir/OE (1–2)
  + audio (1–2) ≈ 37 vs 34 GPIOs on the 20K header.
  Fix: decode A13–A20 externally (e.g. 74HC688 comparator / 74-series decoder) and feed chip selects
  (bank $FF I/O pages incl. VDC/VCE/PSG, banks $80–$87) to the FPGA → saves ~5–6 pins.
- Level shifting: GW2AR I/O is not 5 V-tolerant. 74LVC245 on data, 74LVC244 on address/control.
- Audio out: on-board MAX98357A is a speaker amp, not line-level. Use PWM/sigma-delta + RC filter
  or a small I2S DAC for the analog return to the port.
- On the expansion device the bus interface uses most GPIOs → conflicts with the MiSTeryShield20k
  Pico link/DB9; plan a dedicated carrier board.

## HDMI (phase 2) via bus snooping
- Feed snooped VDC/VCE/PSG writes into shadow copies; render to HDMI; mix PSG + ADPCM + CD-DA digitally.
- Snoop READS too: VDC status reads clear IRQ flags, VRAM data reads auto-increment the read pointer.
- Raster effects need scanline-accurate timing: lockstep with the console clock from reset, or
  anchor with an LM1881 sync separator on the port's composite video (HSYNC/VSYNC on 2 pins) and
  timestamp writes.

## Staged plan
1. De-risk: 20K on the expansion port as a 64 KB RAM responder at banks $80–$87; memory test from a HuCard.
2. CD-only build: bus interface + CD controller + ADPCM + CD-DA + RAM + Pico link. Get games booting.
3. Add shadow VDC/VCE/PSG + HDMI output.

## Side note
- PCEHeroTN beta: Street Fighter II not starting is likely the missing SF2 mapper
  (bank switching via writes to $1FF0–$1FF3 for the 2.5 MB ROM).
